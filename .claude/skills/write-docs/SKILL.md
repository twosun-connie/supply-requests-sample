# 원본 문서 쓰기: $ARGUMENTS

코드를 쓰지 않는다. 문서만 쓴다. 모르는 것은 지어내지 않고 묻는다.

1. **있는 것을 읽는다.** `docs/README.md`(문서 지도), `docs/`의 원본 문서, `supabase/migrations/`, `app/`의 화면 목록, 관련 결정 기록(`docs/decisions/`). 이미 정해진 것을 다시 묻지 않는다.
2. **한 번에 3~5개씩 묻는다.** 답을 받으면 다음 묶음으로 간다. 순서는 아래와 같다.
   1. 누가 쓰는가(역할), 무엇을 하려고 쓰는가, 지금은 어떻게 하고 있는가
   2. 다루는 것(데이터)과 항목, 필수 여부, 길이·범위
   3. 상태가 있는가. 어느 상태에서 어느 상태로 가는가. 누가 바꾸는가
   4. 역할마다 볼 수 있는 것과 할 수 있는 것. 남의 것을 볼 수 있는가
   5. 화면 목록과 화면마다 보이는 것·할 수 있는 것
   6. 하지 않을 것(이번 범위 밖)
3. **문서를 쓴다.** 양식은 이 폴더의 `templates/`를 따른다. 표의 열 이름과 절 제목을 바꾸지 않는다(검사가 읽는다).

| 문서 | 양식 | 내용 |
|---|---|---|
| `docs/rules.md` | `templates/rules.md` | 용어, 데이터 항목, 상태 흐름, 업무 규칙, 하지 않는 것 |
| `docs/permissions.md` | 저장소의 기존 파일 | 역할, 역할별 권한(권한 코드), 행 단위 규칙 |
| `docs/screens.md` | 저장소의 기존 파일에 행을 더한다(없으면 `templates/screens.md`) | 화면 목록: 경로, 누가, 보이는 것, 할 수 있는 것 |
| `docs/schema.md` | 저장소의 기존 파일에 테이블을 더한다(없으면 `templates/schema.md`) | 테이블과 열, 변경 기록. 시작 마이그레이션의 네 테이블은 이미 적혀 있다 |
| `docs/design.md` | `templates/design.md` | 방향, 화면 뼈대, 공통 규칙 |

4. **규칙은 검사할 수 있는 문장으로 쓴다.** "적절히 처리한다"가 아니라 "제출 상태가 아니면 승인할 수 없다". 문장 하나가 테스트 하나가 된다.
5. **권한 코드는 `대상.동작`으로 쓴다.** 예: `requests.approve`. 역할 이름을 규칙에 쓰지 않고 권한 코드를 쓴다.
6. **정책으로 막지 못하는 규칙을 표시한다.** 상태 전이와 열 단위 제한은 규칙 옆에 "강제: 서버 액션" 또는 "강제: DB 트리거"를 적는다(`.claude/rules/database.md` §8).

## 끝낼 때 출력

- 쓴 문서와 바꾼 절
- 사용자가 답하지 않아 비워 둔 곳(문서에 `《확인 필요: …》`로 표시)
- 다음에 할 일: DB가 필요하면 `/new-migration`, 화면이면 `/new-screen`
