# 문서 지도

이 폴더의 문서는 세 종류다. 어느 것을 언제 쓰는지 여기서 정한다.

| 종류 | 파일 | 담는 것 | 쓰는 때 | 고치는 방법 |
|---|---|---|---|---|
| 원본 문서 | `rules.md` `screens.md` `permissions.md` `schema.md` `design.md` | 이 도구가 **어떻게 동작해야 하는가** | 기능을 만들기 **전에** | 내용을 고쳐 쓴다. 지금의 사실만 남긴다 |
| 작업 기록 | `work/《날짜》-《이름》.md` | 작업 하나에서 **무엇을 왜 했는가** | 작업을 시작할 때 만들고 끝낼 때 채운다 | 끝난 기록은 고치지 않는다. 이어지는 작업은 새 기록을 만든다 |
| 결정 기록 | `decisions/《날짜》-《이름》.md` | 되돌리기 어려운 선택과 **이유** | 패키지 추가, 확장 켜기, 파괴적 변경, 민감한 정보의 저장 | 바뀌면 옛 기록의 상태를 「폐기」로 바꾸고 새 기록을 쓴다 |
| 확인표 | `security-checklist.md` | 사람이 대시보드에서 확인하는 설정 | 처음 만들 때, 배포 전 | 확인한 것에 표시한다 |

## 작업 하나의 흐름

```text
요청 → pnpm docs:new work 《이름》 → 요청·계획을 적는다 → (승인) → 구현
     → pnpm verify → 한 일·검증·하지 않은 것·사람이 할 일을 적는다 → 상태를 「완료」로
```

- 원본 문서가 바뀌는 작업이면 원본 문서를 **먼저** 고친다(화면 목록, 규칙, 스키마).
- 작업 기록이 없으면 `pnpm check:docs`가 실패한다. 응답을 끝낼 때와 커밋 전에 자동으로 돈다.
- 남은 일은 `pnpm report:docs`로 본다: 끝나지 않은 작업, 사람이 아직 하지 않은 일, 정해지지 않은 결정.

## 검사가 보는 것과 보지 못하는 것

| 본다 | 보지 못한다 |
|---|---|
| 코드를 바꿨는데 작업 기록이 없음 | 기록의 내용이 사실인지 |
| 기록의 파일 이름, 머리 항목, 절 제목, 상태 값 | 계획이 좋은 계획인지 |
| 끝난 기록에 남은 양식의 안내(`《…》`), 빈 절 | 「하지 않은 것」에 빠진 것이 있는지 |
| 마이그레이션을 더했는데 `schema.md`가 그대로 | `schema.md`의 내용이 마이그레이션과 같은지 |
| 새 화면의 경로가 `screens.md`에 없음 | 화면이 문서대로 동작하는지 |
| 패키지·확장·`destructive-ok`·`sensitive-ok`에 결정 기록이 없음 | 결정의 이유가 타당한지 |

보지 못하는 것은 사람이 읽고, PR을 준비할 때 검토자(`code-reviewer`)가 기록과 변경을 대조한다.

## 목록 파일을 두지 않는 이유

기록의 목록을 파일로 만들면 여러 작업을 나란히 할 때 그 파일에서 충돌한다. 파일 이름이 날짜로 시작하므로 폴더가 곧 목록이다. 현황은 `pnpm report:docs --all`이 그때그때 만든다.
